# 使用有界分类树支持多层级分类

**Status: accepted**

本次需求明确将原先的一级分类边界扩展为有界分类树，变化点是从“暂不支持多层级”改为支持可验证、可维护的三层分类树，而不是允许模型自由生成目录。分类方案改为冻结的分类树，最多三层；一个现有的“分类数量上限”配置（默认 8，范围 3–15）分别限制每个层级的节点数，因此三层树的理论节点总数最多为该上限的三倍；可分类书签较少时，各层有效上限取配置值与可分类书签数的较小值。分类节点按从选定根文件夹开始的完整相对路径逐层复用同名兄弟文件夹，保留已有文件夹名称和内容。分类节点既可以拥有子节点，也可以直接容纳书签；新节点按冻结方案顺序创建，书签按原始遍历顺序追加。预览只提供重命名、删除节点和重新指派书签，删除节点及其子树后相关书签变为待确认。多层级仍沿用 ADR-0005 的整份预览失效规则和 ADR-0006 的全量撤销规则；这两项决策没有被 supersede。

## Considered Options

- 允许无限深度：被拒绝，因为模型可能生成过深或不稳定的目录树，预览、执行和恢复边界难以维护。
- 只允许叶子节点容纳书签：被拒绝，因为通用内容不应被迫归入无意义的末级分类。
- 按全树名称复用文件夹：被拒绝，因为不同路径下的同名节点可能语义不同。
- 支持任意拖拽和新增节点：暂不采用；第一版保留有限编辑能力，避免把分类预览变成通用目录编辑器。
