# 备份为文件、导入只追加

**Status: accepted**

书签备份由用户主动导出为一个 JSON 文件，内容是两个受支持根文件夹（书签栏、其他书签）的完整后代，不含浏览器节点 ID，因此文件可以跨配置文件、跨机器使用。导入先整体校验文件，再由用户确认，然后按根标题写回同名根文件夹并追加在其现有内容之后。这样在撤销只覆盖最近一次操作、浏览器书签 API 又没有事务的前提下，用户仍有一条独立的兜底路径，同时导入永远不会因为文件内容而删除或覆盖用户已有的书签。

## Considered Options

- 导入时先清空再重建原位置：被拒绝，因为一次误选文件就会删除现有书签，且违反“绝不删除浏览器书签”的既有边界。
- 使用浏览器自带的 Netscape HTML 导出格式：被拒绝，因为需要额外的 HTML 解析与转义代码，而 JSON 与现有 TypeScript 类型一一对应。
- 导出时保留浏览器节点 ID 以便精确还原：被拒绝，因为节点 ID 只在同一浏览器配置内有意义，保留它会让文件看起来可精确还原却做不到。
- 导入参与撤销记录：被拒绝，因为撤销的边界是“一次分类操作”，把导入并入会让最近一次整理的撤销语义变得不可解释。
- 导入时丢弃非 HTTP(S) 书签：被拒绝，因为备份的意义是还原用户自己的书签，书签小工具（`javascript:`）与本地文件链接（`file:`）都可能真实存在；分类流程对它们也只是保持不变。浏览器会接受并保存这些地址，导入只在摘要里提示数量，由用户自己决定是否继续。
